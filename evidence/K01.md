## 9. README / CV claim affected

Adds a claim that the project can run a bounded coding task in an isolated
runner. It is scoped in the same section: OS limits are enforced; filesystem,
network and process restrictions are cooperative audit hooks; a timeout alone
is not isolation; result integrity against adversarial in-process code is not
claimed and is deferred to K02. No claim of container-grade or native-code
isolation is made.

## 10. Remaining limitations

- Audit hooks are not a security boundary: `ctypes` or a native extension can
  bypass filesystem, network and process restrictions. OS limits still apply.
- Reads are unrestricted. A sample can read anything the host user can read,
  though secret-looking environment variables are absent.
- POSIX memory enforcement is a 50 ms RSS sample, not an instantaneous cap;
  `RLIMIT_AS` was rejected because it breaks interpreter startup.
- POSIX does not cap process count; children are killed with the process
  group after the fact.
- A sample that introspects the harness can read the nonce and forge a report.
  The nonce defeats naive forging only; tamper-proof grading is K02.
- The task is Python and stdlib-only (`-I -S -B`); native code, notebooks and
  dependency installation are out of scope.
- The base interpreter (not the venv launcher) runs the harness, because a
  venv launcher needs a child process and the job allows one process.

Full discussion in `docs/K01.md`.
