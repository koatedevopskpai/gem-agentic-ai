## 2b. CI command on Linux (authoritative) â€” after the rework

The first CI run failed 25 tests, all with
`TypeError: 'Event' object is not callable`. Reproduced in
`python:3.11-slim`:

```
src/gem_agentic_ai/sandbox.py:561: in run_python
    watchdog.stop()
src/gem_agentic_ai/sandbox.py:436: in stop
    self.join(timeout=1.0)
/usr/local/lib/python3.11/threading.py:1141: in _wait_for_tstate_lock
    self._stop()
E   TypeError: 'Event' object is not callable
```

**Root cause (one line).** `_MemoryWatchdog.__init__` stored its shutdown flag
as `self._stop = threading.Event()`. That shadows `threading.Thread._stop()`,
which CPython calls from `_wait_for_tstate_lock()` while joining the thread.
On Windows the watchdog is never constructed, so the defect could not appear
there; on POSIX every run hit it in `watchdog.stop()`.

**Fix.** Rename the attribute to `_stop_event` (`a457ae7`, three lines).
No test was skipped, weakened or deleted; the POSIX path runs in CI.

## 9. README / CV claim affected

Adds a claim that the project can run a bounded coding task in an isolated
runner. It is scoped in the same section: OS limits are enforced; filesystem,
network and process restrictions are cooperative audit hooks; a timeout alone
is not isolation; result integrity against adversarial in-process code is not
claimed and is deferred to K02. No claim of container-grade or native-code
isolation is made.

## 10. Remaining limitations

- Audit hooks are not a security boundary: `ctypes` or a native extension can
  bypass filesystem, network and process restrictions. OS limits still apply.
- Reads are unrestricted. A sample can read anything the host user can read,
  though secret-looking environment variables are absent.
- POSIX memory enforcement is a 50 ms RSS sample read from `/proc` (Linux
  only), not an instantaneous cap; `RLIMIT_AS` was rejected because it breaks
  interpreter startup. It is now verified on Linux (the demo's 512 MiB
  allocation is killed by the watchdog, Â§5); on macOS `/proc` does not exist, so
  this limit is not enforced there and the platform is untested.
- POSIX does not cap process count; children are killed with the process
  group after the fact.
- A sample that introspects the harness can read the nonce and forge a report.
  The nonce defeats naive forging only; tamper-proof grading is K02.
- The task is Python and stdlib-only (`-I -S -B`); native code, notebooks and
  dependency installation are out of scope.
- The base interpreter (not the venv launcher) runs the harness, because a
  venv launcher needs a child process and the job allows one process.

Full discussion in `docs/K01.md`.
