# C04 — Evidence pack for gem-agentic-ai

Status: implemented on `task/C04-evidence-pack`, based on `52e9398`. This
document records what the evidence pack is, how it was assembled, what it
does and does not prove, and how it stays true after the repository changes.

## Why

A reviewer should not have to reconstruct the project's claims from a README,
a CV and a set of test names. The pack gives one route — README → source →
tests → dated results — and makes the boundaries explicit: exactly-once,
encryption, timeout semantics and sandboxing are the four places where an
agent framework is most often over-described.

The pack also records a claim that was removed. Keeping the removal visible
is part of the evidence: a repository that only lists what it does invites the
reader to assume the rest was checked.

## What was built

| File | Purpose |
|---|---|
| [`EVIDENCE.md`](../EVIDENCE.md) | The reviewer's index: scope, contribution by module, measured results with provenance, the removed claim, reproduction commands, one success and one failure, decision pointers, and what the project does not establish |
| `README.md` | One line at the top pointing at `EVIDENCE.md` |
| This document | The pack's method, scope and maintenance |
| [`evidence/C04.md`](../evidence/C04.md) | The dated run record behind the numbers in `EVIDENCE.md` |

## Method

1. **Only the merged tree counts.** The pack describes `52e9398`, the merge
   of C03, A01, A02, A03 and K01. Unmerged branches are out of scope and are
   not named as capabilities. If a later task merges, re-run the commands and
   update the counts.
2. **Every result names its location.** A test claim points at a test file;
   a measured claim points at an entry in `evidence/` and the command that
   produced it. No metric is copied from a CV or a chat transcript.
3. **The authoritative run is Linux.** The POSIX sandbox branches do not run
   on Windows. K01's first CI run is the example of what a Windows-only
   reading misses: a `Thread._stop` shadowing defect failed 25 tests on
   Linux and could not appear on Windows. The pack quotes the Linux result
   as authoritative and the Windows result as a second platform.
4. **No generated files are committed.** The repository's rule is that logs
   and coverage reports do not enter version control. The raw runs live in
   the task's delivery package (`outputs/claude/C04/artifacts/`); the
   repository records the commands and the summaries in `evidence/C04.md`.
   A reviewer can reproduce every number with the commands in `EVIDENCE.md`.
5. **No paid run.** The suite is offline and uses a scripted model. The live
   demo and the integration test were not run, and the pack says so rather
   than implying a provider result.

## Handling the removed claim

The CV/portfolio wording *"Added plan fingerprints, an execution ledger and
step budgets to bound repeated work"* was classified UNSUPPORTED by the C01
claim register: zero matches in source or README. It was removed, and the
skill lines listing the same terms went with it.

`EVIDENCE.md` records the removal and the absence check:

```bash
git log --all --oneline -S"execution ledger"      # 0
git log --all --oneline -S"plan fingerprint"      # 0
git log --all --oneline -S"step budget"           # 0
git grep -niE "execution ledger|plan fingerprint|step budget" HEAD   # 0
```

The only "ledger" in the repository is the in-memory demo ticket list in
`tools/actions.py`, plus prose about idempotency records. Neither is an
execution ledger, and the pack says so instead of leaving the word to imply
a capability.

## What the pack does not establish

- It is not an independent reproduction. The results were produced by the
  same person who wrote the code, on one Windows host and one Linux
  container. That is evidence of behaviour, not of a third-party audit.
- It does not cover provider behaviour, latency, cost or answer quality: no
  live model call was made.
- It does not cover deployment, uptime, multi-tenancy or scale. There is no
  hosted service to observe.
- It does not make the K01 runner a security boundary. The pack repeats the
  runner's own limits rather than upgrading them: cooperative audit hooks,
  OS limits where available, sampled memory enforcement, unrestricted reads,
  forgeable nonce, macOS untested.
- It does not claim exactly-once execution. A tool without a stable action
  key is at-least-once across a crash, and the dual-write window is open.

## Acceptance criteria

| Criterion | Where |
|---|---|
| Same shape as the merged `enterprise-rag-pipeline/EVIDENCE.md` | `EVIDENCE.md`: what it is, contribution, measured results, removed claim, reproduction, success/failure, decisions, "what this does not establish" |
| Reviewer can go README → source → tests → dated results in under five minutes | `README.md` links `EVIDENCE.md`; the five-minute path links to code paths, test files and `evidence/` |
| No claim exceeds what the repository records | Every measured value is from `evidence/C04.md` or an existing `evidence/` file; `python -m pytest` counts are reproducible; live/provider/deployment claims are explicitly absent |
| Explicit coverage of at-least-once tools, one unencrypted SQLite file, a non-killed timeout, and the guard not being a sandbox | `EVIDENCE.md` "What this does not establish", first four bullets |

## Alternatives considered

- **Commit the raw pytest logs into `evidence/`.** They are machine output
  with absolute paths, they churn on every run, and the repository already
  keeps generated files out of version control. The summaries and exact
  commands are recorded instead; the raw logs are in the delivery package.
- **Copy the C01 claim register into the repository.** The register covers
  twelve repositories and is owned by the cross-repository task. `EVIDENCE.md`
  states the one row that concerns this project and the check that supports
  it, and leaves the register where it belongs.
- **Describe only the happy path.** Rejected: the POSIX CI failure is the
  strongest evidence that the Linux verification is real, and the four
  "does not establish" bullets are exactly where a reviewer would otherwise
  assume more than the code provides.
- **Include unmerged branch work (A05, A06).** Rejected: the pack must match
  the tree it ships with. A pack that cites code the branch does not contain
  is the failure mode this task exists to prevent.

## Maintenance

When a task merges, re-run:

```bash
ruff check .
pytest -m "not integration" -q
```

Update the counts and date in `EVIDENCE.md`'s "strongest measured results"
and in `evidence/C04.md`, or add a new dated entry. Do not carry a number
forward without a run that produced it.
