# A05 — Async API with streaming, cancellation and session ownership

Status: implemented on `task/A05-async-streaming-api`, based on `52e9398`
(main after A02, A03 and K01). This document records the design, the
cancellation failure that shaped it, the measured latency and the limits.
The task file calls for a measured latency figure, an end-to-end client demo
covering disconnect, timeout and resume, proof that a cancelled request
stops work rather than only closing the socket, and proof that one user
cannot read another user's session.

## Why

The agent could be driven only in-process, through the CLI. An API needs
three properties that the CLI never had to demonstrate:

1. **Streaming.** The answer arrives as the model produces it, not after it
   is complete.
2. **Cancellation.** When a client leaves, the work stops. A closed socket
   that leaves the model generating into a discarded queue is not
   cancellation; it is a leak with better manners.
3. **Ownership.** A session belongs to an authenticated user. A token or id
   from one user must not read another user's conversation.

The third property builds on A02: sessions are durable LangGraph threads
scoped by user. This task exposes them over HTTP rather than inventing a
second store.

### Endpoints

| Method | Path | Behaviour |
|---|---|---|
| `POST` | `/sessions` | Create a durable session for the authenticated user; `201` |
| `GET` | `/sessions` | List that user's sessions only |
| `GET` | `/sessions/{id}` | Rehydrate: message history and `awaiting_reply` |
| `DELETE` | `/sessions/{id}` | Remove the session; `204` |
| `POST` | `/sessions/{id}/messages` | One turn, streamed as SSE |
| `GET` | `/healthz` | Liveness without a token |

Another user's session id returns `404`, deliberately identical to an id
that does not exist. The API must not confirm the existence of a session
the caller cannot access.

### Session ids

The client sees the same opaque storage id A02 mints (`uuid4().hex`). It
never supplies a user id, and it cannot choose a thread key. `SessionService`
resolves `(authenticated user, opaque id)`; a mismatch is `SessionNotFound`,
which the handler maps to `404`.

## The SSE protocol

One POST per turn. The response is `text/event-stream`:

```
event: token
data: {"text": "Hel"}

event: token
data: {"text": "lo"}

event: done
data: {"text": "Hello", "timing": {"first_token_ms": 73.2, "total_ms": 390.6, "tokens": 2}}
```

An error ends the stream instead of `done`, with a machine-readable code:

```
event: error
data: {"code": "timeout", "message": "the turn exceeded its 0.15s deadline and was cancelled", "timing": {...}}
```

Codes: `timeout`, `agent_error`, `internal_error`. Validation failures
(empty message, oversized message, deadline outside 0.05–300 s) are `422`
before a stream starts; one concurrent turn per session is `409`.

Only model-node chunks (`metadata["langgraph_node"] == "model"`) are
forwarded, so tool output is not shown as assistant text. **Modalities
implemented: text only.** No images, audio or files.

## Cancellation: what failed and why

The first implementation cancelled the task consuming `agent.astream` and
closed the stream. The socket closed and the unanswered question was rolled
back, but the model kept producing tokens: `emitted` kept climbing after
the client had gone. Closing an async generator is not cancelling a
LangGraph run.

Two mechanisms were needed, and the order in which they were found matters.

1. **Deliver cancellation inside the task that iterates the agent stream.**
   `stream_turn` consumes it in an internal `drive()` task and puts chunks
   on a queue. Cancelling that task raises `CancelledError` inside
   `__anext__`, which LangGraph treats as cancellation of the run. It also
   closes the stream explicitly in `finally`, because cancellation can
   arrive while the task is suspended between iterations.
2. **Run the turn on its own event loop in a worker thread.** This was not
   obvious and was the actual blocker under uvicorn. Starlette runs each
   response inside an AnyIO cancel scope. When the client disconnects the
   scope is cancelled, and the server *re-cancels* every task created inside
   it on each event-loop iteration until the response ends. Each resume of
   an await inside that task tree is interrupted again. LangGraph's shutdown
   (`AsyncPregelLoop.__aexit__` → `AsyncBackgroundExecutor.__aexit__`) is
   exactly such a sequence of awaits, so it never reached the point where it
   cancels the node tasks running the model. The cancellation was delivered,
   then interrupted, repeatedly.

`ThreadedTurn` owns one turn on a fresh event loop in a thread named
`agent-turn`. The request coroutine only forwards events, bridged with
`loop.call_soon_threadsafe`. Cancelling the turn is exactly one
`task.cancel()` on that loop, and the cleanup that follows — LangGraph's
shutdown, stream close, rollback — runs on a loop the HTTP request cannot
interrupt. The worker publishes a `None` sentinel after the rollback, so
the request knows the turn is completely finished before the response ends.

The tests assert the property, not the plumbing: the scripted model records
that its stream was cancelled, and the demo records that the token count did
not move in the 300 ms after cancellation. `test_api_server.py` exercises
the same path behind a real uvicorn socket; `test_api_streaming.py` proves
the class on a plain loop and repeats deterministically.

### Cleanup and rollback

LangGraph checkpoints the user message before the model runs. An
interrupted turn without cleanup would leave a question with no answer, and
the next turn would send two consecutive user messages to the model.
`_rollback` removes the last message only if it is still this turn's
unanswered `HumanMessage`; an answer that was already checkpointed is left
alone. The SQLite work runs in a worker thread and is shielded so a second
cancellation cannot abandon it halfway. Rollback happens **after** the run
is stopped, so it cannot race a model still writing checkpoints.

## Deadlines

The per-turn deadline defaults to 30 s and is clamped to 0.05–300 s. It is
implemented with `asyncio.timeout` around the queue loop, on the turn's own
loop. On expiry the run is cancelled by the same path as a disconnect and
the client receives `error: timeout`, then the question is rolled back. A
timed-out turn does not leave a half-open lock: the session is immediately
usable again.

**A timed-out tool is not killed.** The deadline stops the turn; Python
cannot interrupt a thread, so a non-cooperative tool may keep running after
its result is discarded. This is the same limitation as A03, stated again
because the API's deadline makes it more visible.

## Concurrency and state

- Each turn builds its own graph and guard, so two sessions never share a
  budget or idempotency window.
- A second POST to the same session while a turn runs is `409`. The check
  and the claim happen without an await, on one event loop.
- The turn runs on its own loop. The A02 `_ScopedCheckpointer` gained
  `aget_tuple`, `alist`, `aput` and `aput_writes`, which delegate to the sync
  saver with `asyncio.to_thread`. The SQLite connection is already opened
  with `check_same_thread=False` and a busy timeout. Serialisation comes from
  the one-turn-per-session rule, not from a process-wide lock.
- A rehydrating `GET` is answered by the request loop directly (the stored
  history), so it does not wait on an in-flight turn.

## Measured latency

`scripts/a05_demo.py` drives the real application under uvicorn over
loopback with a scripted model streaming one token every 50 ms. Over 20
turns it measured (Linux, `python:3.11-slim`):

| Measurement | Median | p95 |
|---|---|---|
| Client first token | 78.2 ms | 80.1 ms |
| Client total | 347.0 ms | 363.5 ms |
| Server first token | 65.8 ms | 67.6 ms |
| Server total | 332.3 ms | 334.3 ms |
| Client-observed overhead beyond server timing | 12.4 ms | 14.6 ms |

The scripted cadence dominates: six tokens × 50 ms is 300 ms by
construction. The column that describes the API itself is the last one —
about 12–15 ms for request handling, SSE framing, transport and client
parsing. **These are not provider latency figures.** No model provider was
called. The full run, including the Windows figures, is in
`evidence/A05.md`.

## End-to-end demo

`scripts/a05_demo.py` runs six scenarios and writes a JSON report:

| Scenario | What it establishes |
|---|---|
| latency | First-token and total latency over 20 turns |
| disconnect | The socket closes, the model stops (token count frozen), the question is rolled back, the session answers again |
| timeout | `error: timeout` is delivered, the model is cancelled, history is clean |
| resume | After an abandoned turn, the next turn sees the first exchange and not the abandoned question |
| ownership | Another user gets `404` on GET, POST and DELETE and does not see the session in their list |
| validation | Empty message and out-of-range deadline are `422` |

Run from the repository root:

```bash
python scripts/a05_demo.py --out artifacts/a05_demo.json
```

Exit status is 0 only when every check passes. Windows and Linux runs both
pass; the captured reports are in the delivery package.

## Alternatives considered

- **WebSockets.** The agent needs no client-to-server frames mid-turn.
  SSE keeps one request per turn, which makes ownership, cancellation and
  the 409 rule simpler; proxies handle it.
- **Polling for tokens.** Adds latency and a server-side buffer whose
  lifetime must be managed. Not a streaming API.
- **Cancelling the response task in place (no worker loop).** Fails for the
  AnyIO reason above: the cleanup is interrupted before it cancels the node
  tasks. This was measured, not assumed.
- **`context=contextvars.Context()` on the producer task.** Worked in a
  simple AnyIO probe, not in the real LangGraph shutdown.
- **A process per turn.** A stronger isolation boundary, but a much larger
  operational change; the loop-per-turn keeps one process and one SQLite
  store.
- **JWT/OIDC.** The token map exists to prove an authenticated user id
  reaches the session layer. A real deployment replaces
  `TokenAuthenticator`; the rest of the API is unchanged. Not implemented
  and not claimed.

## What this does not establish

- **Text only.** No other modality.
- **The token map is a demo authenticator.** Tokens are static, held in the
  environment, and not rotated or revoked. There is no OIDC, no rate
  limiting and no multi-tenancy beyond a user id.
- **One process, one SQLite file.** No horizontal scaling, no shared turn
  registry. `active_turns` is process-local, so two replicas could accept
  concurrent turns for one session.
- **The deadline stops the turn, not the world.** A tool running in a
  thread may outlive its result; a timed-out tool is not killed.
- **The guard is not a sandbox.** A03's execution policy applies unchanged.
- **Latency figures are API-layer figures.** They do not include a provider
  or a real network. The demo is loopback.
- **No backpressure tuning.** SSE frames are yielded as produced; a slow
  client increases the queue depth between the worker and the response.
